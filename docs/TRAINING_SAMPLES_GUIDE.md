# 训练样本数量选择指南

## 📊 MNIST 数据集结构

```
MNIST 标准划分:
├── 训练集: 60,000 样本
│   └── 用途: 训练模型、学习特征、STDP学习
└── 测试集: 10,000 样本
    └── 用途: 评估性能、聚类分析
```

---

## 🎯 `--n_train 60000` 的含义

### ✅ 是的，这代表**完整实验**！

**原因**：

1. **MNIST 训练集正好是 60,000 样本**
   - 这是 MNIST 数据集的标准训练集大小
   - 由 Yann LeCun 等人创建时就是这个划分

2. **`--n_train 60000` 表示使用全部训练数据**
   ```python
   # 在代码中
   if args.n_train is not None:
       train_data = dataset['train_data'][:args.n_train]  # 取前 n_train 个
   else:
       train_data = dataset['train_data']  # 全部（60,000）
   ```

3. **标准实验设置**
   - 学术论文通常使用全部 60,000 训练样本
   - 这样结果可以与其他论文对比

---

## 📈 不同样本数量的选择

### 🧪 实验场景对比

| 场景 | n_train | 用途 | 训练时间 | 性能 |
|------|---------|------|---------|------|
| **快速测试** | 100-1000 | 验证代码、调试 | ~1-5 分钟 | 很差 (~30-40%) |
| **小规模实验** | 5,000-10,000 | 快速原型、参数调优 | ~10-30 分钟 | 中等 (~50-60%) |
| **标准实验** | 60,000 | 完整训练、论文结果 | ~1-2 小时 | 最佳 (~85-95%) |
| **全部数据** | 60,000 | 同上（MNIST无更多） | ~1-2 小时 | 最佳 |

## 🔬 为什么选择 60,000？

### 1. **数据集标准划分**

MNIST 由 Yann LeCun 等人创建，标准划分为：

```
原始数据集:
├── NIST Special Database 3 (SD-3)
│   └── 250,000 个手写数字
└── NIST Special Database 1 (SD-1)
    └── 250,000 个手写数字

MNIST 处理后:
├── 训练集: 60,000
│   ├── SD-3: 30,000 (NIST Training Dataset)
│   └── SD-1: 30,000 (NIST Training Dataset)
└── 测试集: 10,000
    ├── SD-3: 5,000 (NIST Test Dataset)
    └── SD-1: 5,000 (NIST Test Dataset)
```

### 2. **学术标准**

- 📚 **几乎所有论文**都使用 60,000 训练样本
- 📊 **可对比性**：与其他研究结果直接对比
- 🎯 **足够的数据量**：
  - 10 类，每类 ~6,000 样本
  - 足够学习有意义的特征

### 3. **实际考虑**

- ⚖️ **数据量平衡**：
  - 不会太少（不够学习）
  - 不会太多（计算负担）
- 💾 **内存友好**：60,000 × 784 ≈ 180 MB（可接受）
- ⏱️ **时间可控**：1-2 小时（可接受）

## 💡 如何选择 `n_train` 参数

### 场景 1: 快速代码验证 ⚡

```bash
# 目的: 验证代码能跑通，不在乎性能
python train.py --n_train 100 --n_epochs 1 --device cpu
```

**特点**:
- ⏱️ 时间: ~1-2 分钟
- 📊 性能: 很差（NMI ~0.2-0.3）
- ✅ 用途: Debug、快速迭代

---

### 场景 2: 参数调优 🔧

```bash
# 目的: 测试不同参数设置，找到最佳配置
python train.py --n_train 5000 --n_epochs 1 --device cuda
```

**特点**:
- ⏱️ 时间: ~10-20 分钟
- 📊 性能: 中等（NMI ~0.5-0.6）
- ✅ 用途: 超参数搜索、快速实验

**建议**:
- 使用 5,000-10,000 样本
- 保持其他参数与完整实验一致
- 找到最佳参数后，用 60,000 重新训练

---

### 场景 3: 论文/正式结果 📝

```bash
# 目的: 获得最佳性能，可与论文对比
python train.py --n_train 60000 --n_epochs 1 --device cuda
```

**特点**:
- ⏱️ 时间: ~1-2 小时（GPU）或 ~5-10 小时（CPU）
- 📊 性能: 最佳（NMI ~0.6-0.7，预期）
- ✅ 用途: 最终结果、论文实验

**建议**:
- ✅ 使用全部 60,000 样本
- ✅ 设置合理的 seed（重现性）
- ✅ 保存模型权重
- ✅ 多次运行（不同 seed）报告均值±标准差

---

### 场景 4: 消融实验 🔬

```bash
# 目的: 研究数据量对性能的影响
for n in 1000 5000 10000 30000 60000; do
    python train.py --n_train $n --seed 0
done
```

**用途**: 
- 研究学习曲线
- 分析数据效率
- 理解模型容量

## 📊 不同 `n_train` 的性能预期

### Diehl & Cook (STDP) 预期性能

| n_train | 训练时间 (GPU) | NMI (预期) | ARI (预期) | ACC (预期) | 推荐用途 |
|---------|---------------|-----------|-----------|-----------|---------|
| **100** | ~1 分钟 | 0.20-0.30 | 0.10-0.20 | 0.30-0.40 | Debug |
| **1,000** | ~5-10 分钟 | 0.35-0.45 | 0.25-0.35 | 0.45-0.55 | 快速测试 |
| **5,000** | ~20-30 分钟 | 0.45-0.55 | 0.35-0.45 | 0.55-0.65 | 参数调优 |
| **10,000** | ~30-50 分钟 | 0.50-0.60 | 0.40-0.50 | 0.60-0.70 | 快速实验 |
| **30,000** | ~1-1.5 小时 | 0.55-0.65 | 0.45-0.55 | 0.65-0.75 | 接近完整 |
| **60,000** ⭐ | ~1-2 小时 | **0.60-0.70** | **0.50-0.60** | **0.65-0.75** | **论文结果** |

**关键观察**:
- 📈 性能随数据量增加而提升
- 📉 收益递减：30,000 → 60,000 提升较小
- ⚖️ 权衡：时间 vs 性能

## 🎯 实际建议

### 推荐工作流程

#### 第 1 阶段: 快速验证 ✅

```bash
# 用少量数据验证代码
python train.py --n_train 1000 --n_epochs 1 --device cpu
```

**时间**: ~10 分钟  
**目的**: 确保代码能跑通

---

#### 第 2 阶段: 参数调优 🔧

```bash
# 用中等数据量找最佳参数
python train.py --n_train 5000 --n_epochs 1 --device cuda \
    --lr 1e-4 --n_neurons 400

python train.py --n_train 5000 --n_epochs 1 --device cuda \
    --lr 1e-3 --n_neurons 400

# 比较结果，选择最佳
```

**时间**: ~20-30 分钟/次  
**目的**: 找到最佳超参数

---

#### 第 3 阶段: 完整训练 🚀

```bash
# 用找到的最佳参数，在全部数据上训练
python train.py --n_train 60000 --n_epochs 1 --device cuda \
    --lr 1e-4 --n_neurons 400  # 使用第2阶段找到的最佳参数
```

**时间**: ~1-2 小时  
**目的**: 获得最终结果

---

#### 第 4 阶段: 统计显著性 📊

```bash
# 用不同 seed 重复实验
for seed in 0 1 2 3 4; do
    python train.py --n_train 60000 --seed $seed --device cuda
done

# 报告: NMI = 0.65 ± 0.02 (mean ± std over 5 runs)
```

**时间**: ~5-10 小时  
**目的**: 论文中报告均值±标准差

## 🔍 深入理解：为什么不是 70,000？

### MNIST 没有更多数据了！

MNIST 数据集固定为：
- ✅ 训练集: 60,000
- ✅ 测试集: 10,000
- ❌ 没有更多数据

**如果你想要更多数据**:

1. **使用数据增强**（不推荐用于 STDP）
   ```python
   # 旋转、平移、缩放等
   # 但 STDP 学习对这些变换敏感
   ```

2. **使用更大的数据集**
   - Fashion-MNIST: 也是 60,000 + 10,000
   - EMNIST: ~240,000 训练样本
   - CIFAR-10: 50,000 训练样本

3. **组合数据集**（不推荐）
   ```python
   # MNIST + Fashion-MNIST
   # 但这会改变任务定义
   ```

## 💡 实用技巧

### 1. 从小到大渐进式训练

```bash
# 第1步: 验证代码
python train.py --n_train 100

# 第2步: 如果成功，增加到 1000
python train.py --n_train 1000

# 第3步: 如果成功，增加到 5000
python train.py --n_train 5000

# 第4步: 最终完整训练
python train.py --n_train 60000
```

### 2. 使用比例而非绝对数量

```python
# 在代码中可以这样写
import argparse
parser.add_argument('--n_train_ratio', type=float, default=1.0,
                    help='Fraction of training data to use (0-1)')

# 使用
n_train_samples = int(len(train_data) * args.n_train_ratio)
# 如果 n_train_ratio=0.1，则 n_train_samples=6000
```

### 3. 保存检查点

```python
# 每训练 10,000 样本保存一次
if (i + 1) % 10000 == 0:
    torch.save(network.state_dict(), 
               f'checkpoint_{i+1}.pt')
```

这样即使中断也可以恢复。
